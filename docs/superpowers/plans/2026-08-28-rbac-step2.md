# STEP 2 인증·RBAC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ADMIN과 USER 권한을 Supabase DB, Next.js 서버, 사용자 화면에서 일관되게 강제한다.

**Architecture:** `core.app_user`와 `core.is_admin()`이 권한의 단일 기준이다. SSR 쿠키 세션 클라이언트와 auth helper가 서버 요청을 검증하고, RLS와 관리자 RPC가 직접 호출도 차단한다.

**Tech Stack:** Next.js 15, React 19, TypeScript, Supabase Auth, `@supabase/ssr`, PostgreSQL RLS

**Spec:** `docs/superpowers/specs/2026-08-28-rbac-design.md`

## Global Constraints

- service role key를 브라우저 또는 `NEXT_PUBLIC_*` 환경 변수에 넣지 않는다.
- anon에게 업무 데이터 쓰기 권한을 부여하지 않는다.
- 관리자 변경은 `requireAdmin()`과 DB RLS/RPC를 모두 거친다.
- 계산용 raw/core/analytics SQL은 권한 변경 외에 수정하지 않는다.

### Task 1: DB 권한 기반 구축

**Files:** Create `supabase/migrations/20260828000100_auth_rbac.sql`; Modify `sql/01-grants.sql`, `sql/02-policies.sql`

- [ ] 기존 anon grant와 수업용 `using (true)` 정책을 명시적으로 revoke/drop한다.
- [ ] `core.app_user`, `core.audit_log`, 신규 Auth 사용자 트리거, `core.is_admin()`, `updated_at` 트리거를 만든다.
- [ ] 활성 authenticated 사용자 조회 정책과 ADMIN 전용 mutation 정책을 만든다.
- [ ] `core.admin_update_user(uuid, text, boolean)` RPC에서 actor의 ADMIN 여부·자기 role 하향·자기 비활성화를 검사하고 audit log를 기록한다.

### Task 2: SSR 세션과 서버 권한 helper

**Files:** Modify `lib/supabase/server.ts`, `lib/supabase/client.ts`, `lib/supabase.ts`, `lib/supabase/env.ts`; Create `lib/auth.ts`, `middleware.ts`

- [ ] `cookies()` 기반 server client와 브라우저 `createBrowserClient`를 구성한다.
- [ ] `getRole()`, `requireUser()`, `requireAdmin()`을 구현한다.
- [ ] middleware에서 `/login`, 정적 파일, API health를 제외한 보호 경로를 next 쿼리와 함께 리다이렉트한다.
- [ ] `/admin/*` 요청은 역할을 조회해 USER에는 403 응답을 낸다.

### Task 3: 로그인과 로그아웃

**Files:** Modify `app/(auth)/login/page.tsx`; Create `app/(auth)/login/actions.ts`, `components/auth/login-form.tsx`, `components/auth/logout-button.tsx`

- [ ] Server Action에서 password sign-in을 호출하고 실패 메시지와 안전한 next 경로를 반환한다.
- [ ] 로그인 성공 시 next 또는 `/`로 이동한다.

### Task 4: ADMIN 사용자 관리

**Files:** Create `app/(admin)/admin/users/page.tsx`, `app/(admin)/admin/users/actions.ts`, `components/admin/user-management-table.tsx`; Modify `app/(admin)/layout.tsx`, `lib/menu.ts`

- [ ] 사용자 목록은 server client로 `core.app_user`만 조회한다.

- [ ] 메뉴는 ADMIN 목록에 `/admin/users`를 추가하고 USER 메뉴에는 노출하지 않는다.
